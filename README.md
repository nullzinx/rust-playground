#🦀 Learning Rust

## What is this repository?

This repository documents my journey learning Rust, from writing my first lines of code to building complete software.

I divided the journey into four stages:

- Stage 0 — First lines of code in Rust (termined)
- Stage 1 — My first basic CLI programs in Rust (current)
- Stage 2 — My first APIs and CRUD implementations
- Stage 3 — My first complete web service or software application in Rust

---

## Stage 0 — Why Rust?

I was already quite comfortable with Python, but I wanted to spend some time learning another language.

Rust caught my attention because of its performance, memory safety, and low-level control. At the same time, I had been slowly developing an aversion to Python, perhaps because it reminds me of a past that I don't want to go into detail about, but that was never particularly pleasant.

I also started questioning how much Python's abstractions and simplicity were contributing to my own stagnation. I wanted to understand more of what was happening underneath the abstractions instead of always relying on them.

So I decided to move away from Python where possible and learn something fundamentally different.

At the beginning

At first, I felt completely lost. I didn't know where to start, what to study, or where to find decent learning material.

Rust's concepts were unfamiliar, and the compiler often seemed to be fighting against me.

Over time, however, things started to make sense. I gradually became more comfortable with ownership, borrowing, types, error handling, Cargo, and the general way Rust programs are structured.

---

## Stage 1 — My first tools in Rust

After some time and a lot of studying, I started to get the hang of Rust.

I can now build basic software using crates such as "clap" and "rand", work with Cargo, handle files, parse command-line arguments, and create CLI tools.

As part of this stage, I built two small CLI programs:

- QMATH — a small mathematical expression generator.
- Hexdump — a tool for inspecting binary data.

These projects allowed me to put what I had learned into practice, especially argument parsing, file handling, iteration, and working with external crates.

As the final project for this stage, I also created NLAP, my own command-line argument parser.

Rather than relying entirely on an existing argument-parsing library, I wanted to understand how this kind of functionality could be implemented from scratch.
